# Volt

Volt is a Flutter learning-management app for lecturers (dosen) and students (mahasiswa). Lecturers create classes, materials (materi), assignments (tugas), and logic-gate simulations; students join classes, read materials, and submit assignments.

The UI is in Indonesian. Code comments are mixed Indonesian and English.

## Tech stack

- Flutter / Dart (SDK `^3.9.2`)
- **Supabase** (`supabase_flutter`): backend and file storage (materials, submissions)
- Firebase (Auth, Cloud Firestore) and `firebase_storage`: currently still used by most features. See the [Backend status](#backend-status) section.
- SQLite (`sqflite`): a local-only version of the screens under `SQF/` folders. It is not used by the current entry point. Planned for offline downloads.

## Requirements

- Flutter SDK (stable channel), with Dart `3.9.2` or newer
- Android Studio or VS Code with the Flutter extension
- A Supabase project (URL and anon public key)
- Firebase config files for your own Firebase project (see [Firebase setup](#firebase-setup))

## Setup

1. Clone the repository and get packages:

   ```bash
   git clone https://github.com/aaliyahazzahra/project_volt.git
   cd project_volt
   flutter pub get
   ```

2. Create the local Supabase config. The real file is git-ignored:

   ```bash
   cp config/supabase.example.json config/supabase.json
   ```

   Fill in `SUPABASE_URL` and `SUPABASE_ANON_KEY` from your Supabase dashboard (Project Settings → API). Only the **anon public** key goes in the app. Never put the `service_role` key in this project.

3. Firebase setup (see below) so that `lib/firebase_options.dart` and `android/app/google-services.json` exist.

## Running

Pass the Supabase config with `--dart-define-from-file`:

```bash
flutter run --dart-define-from-file=config/supabase.json
```

If the file is missing, the app stops at startup with a `StateError` that names the missing values.

## Testing

```bash
flutter test
```

Current tests are unit tests for the data models in `test/data/`:

- `simulation_component_test.dart`: `SimulationComponent` parsing, serialization, and `copyWith`
- `tugas_firebase_model_test.dart`: `TugasFirebaseModel.fromMap` with optional and invalid fields

Screens and services are not covered yet.

## Project structure

```
lib/

├── data/
│   ├── firebase/    Firebase models and services (+ Supabase storage service)
│   ├── SQF/         SQLite database helper and models
│   └── simulation_models.dart
├── features/        one folder per screen group (0_splash … 5_simulasi)
│   └── */Firebase, */SQF   two parallel screen implementations (see status)
├── widgets/         shared widgets
└── main.dart        app entry, Firebase + Supabase initialization
test/                unit tests
config/              Supabase config (example committed, real file ignored)
```

## Backend status

The app is moving to Supabase as its single backend. The migration is in progress:

| Area | Current | Target |
|---|---|---|
| Storage (files) | Supabase Storage | Supabase Storage |
| Auth | Firebase Auth | Supabase Auth |
| Database | Cloud Firestore | Supabase Postgres |
| Offline (downloads) | not yet | SQLite (`sqflite`) |

The `SQF/` and `Firebase/` screen folders duplicate each other. Keep only the one that matches the active backend when the migration is done.

## Firebase setup

Firebase config is still required for the current build. Files:

- `lib/firebase_options.dart` (generated by `flutterfire configure`)
- `android/app/google-services.json`

These files are tracked in git for now. They are client identifiers, not server secrets, but they are still tied to a specific Firebase project. Remove them from the repo once Firebase is fully replaced.
